# Security Policy

## Reporting a vulnerability

**Please do not report security issues in a public GitHub issue.**

This repository is public, so anything filed here is visible to everyone — including
before we have a chance to fix it.

Report vulnerabilities privately in either of these ways:

- **GitHub** — open a report through
  [Private vulnerability reporting](https://github.com/SignUpBreeze/docs/security/advisories/new).
  Only SignUpBreeze maintainers can see it.
- **Email** — write to **hello@signupbreeze.com** with `SECURITY` in the subject line.

We aim to acknowledge reports within 3 business days.

## Scope

This repository contains the **source of the SignUpBreeze documentation site** only —
MDX pages, configuration, images, and styles. It contains no application code.

Report here if you find:

- Content in these docs that discloses something it shouldn't (credentials, internal
  hostnames, personal data in screenshots, security internals).
- A problem with how the documentation site itself is built or served.

**Vulnerabilities in the SignUpBreeze product** — anything at `signupbreeze.com` or in
the app — should also go to **hello@signupbreeze.com**, not to a public issue in this
repository.

## What not to report

Documentation errors, broken links, typos, and out-of-date instructions are not security
issues. Please open a normal [issue](https://github.com/SignUpBreeze/docs/issues) or a
pull request for those — they're very welcome.

## Disclosure

Please give us a reasonable opportunity to fix an issue before disclosing it publicly.
We'll keep you updated on progress and credit you when the fix ships, unless you'd
rather stay anonymous.
